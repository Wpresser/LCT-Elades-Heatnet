# Конкурсный набор + дороги из OpenStreetMap

Эксперты на встрече после финальной сдачи предложили два шага:
- добавить к набору полигоны автомобильных дорог, чтобы увидеть коридоры между зданиями и дорогами;
- проверить скорость на наборе с дорогами.

Этот сценарий — воспроизводимая обогащённая **копия** набора. Исходный файл `task/sources/Датасет скорректированный.geojson` не меняется.

| Файл | Что это |
|---|---|
| `source/query.overpassql` | запрос Overpass по охвату конкурсного набора |
| `source/overpass_raw.json` | сохранённый ответ Overpass |
| `make_osm_roads.py` | конвертер: линии highway → полигоны `restriction_type = road` |
| `enriched.geojson` | исходные объекты набора + 20 полигонов дорог (`id` вида `osm_road_N`) |
| `manifest.json` | источник, время получения, дата данных OSM, хеши, ширины, допущения |

Время получения и SHA-256 сырого ответа записаны в `manifest.json`. Дорог из `osm_roads` нет в исходном наборе. Их ID в отдельном пространстве имён, исходные ID не меняются.

**Допущение.** Площадных полигонов проезжей части в OSM для этого района нет. Поэтому полигон строится буфером осевой линии дороги на половину ширины. Ширина берётся по приоритету:
1. тег `width`;
2. `lanes × 3,5 м`;
3. типовая ширина класса — таблица в `make_osm_roads.py`.

Из полигонов вычитаются здания и другие ограничения набора. Это приближение для проверки алгоритма, а не достоверная граница проезжей части.

Пересоздать (без сети, из сохранённого ответа):

```bash
python scenarios/osm_roads/make_osm_roads.py scenarios/osm_roads/source/overpass_raw.json \
  "task/sources/Датасет скорректированный.geojson" scenarios/osm_roads \
  --fetched-at "<время из manifest.json>" --source-url "<url из manifest.json>" \
  --query scenarios/osm_roads/source/query.overpassql
```

Файл называется `enriched.geojson`, а не `input.geojson`. Поэтому быстрые `ScenarioTest` и `check_scenarios.py` его не берут: набор тяжёлый, его прогоняют через API отдельно. Сервису он подаётся как обычный вход.
