# Валидатор результата (ЛЦТ 2026, задача 2)

Независимая проверка выходного GeoJSON по техническому приложению и разъяснениям.
Общего кода с Java-сервисом нет: справочники переписаны в `rules.py` прямо из таблиц 1–2.

## Установка

```bash
cd validator
python3 -m venv .venv
.venv/bin/pip install --only-binary=:all: -r requirements.txt
```

## Запуск

```bash
.venv/bin/python validator.py ВХОД.geojson РЕЗУЛЬТАТ.geojson [--json отчёт.json] [--node-tol 0.01]
```

Код возврата: 0 — ошибок нет, 1 — есть нарушения, 2 — файлы не читаются.

## Что проверяется

- Формат §7.1–7.2: типы объектов, обязательные атрибуты, уникальность id, `variant_id`, геометрии.
- Ссылки `start_node_id`/`end_node_id` и совпадение узлов с концами линий (допуск 0,01 м).
- Топология: нет циклов, ровно одно присоединение на связную часть, разветвления только в камерах,
  ≤ 4 примыканий с учётом существующих, `technical_node` ровно с двумя участками, правило 10 м (§2.4).
- Геометрия: поворот ≤ 90°, новые линии не пересекаются вне общих узлов, мелкие изломы (предупреждение).
- Ограничения таблицы 2: отступы от внешнего габарита, запрет пересечений, финальный подход в свой ОКС
  через ближайшую точку границы (§2.2), спецпроходы (прямой участок, границы, угол ≥ 45° для дорог и трамвая,
  Kспец по наибольшему коэффициенту), пересечение существующей теплосети.
- Расходы по дереву сети, ДУ по пропускной способности, неубывание ДУ к присоединению,
  неизменность ДУ при неизменном расходе, предельная длина по каждому пути.
- Пересчёт длин (EPSG:32637), стоимостей участков и камер, врезок, штрафов, score, списка неподключённых и rank.

Спорные трактовки правила конечного участка — в [`../docs/TERMINAL_POLICY_DECISION.md`](../docs/TERMINAL_POLICY_DECISION.md).
