# Финальная доработка и строгая проверка

За основу взят переданный капитаном архив `Elades_Seryoge_19.10_v3.zip` (SHA-256 `63ac3041ab0180073e9e8ec88d93f0f77a068a09a64e38fd2975a4968b0e6245`), применённый к `08ee21f`. Следующие исправления сделаны после двух независимых ревью исходников и требований; проверяющие искали основания отклонить решение, а не только подтверждали зелёные тесты.

## Исправлено

1. **Коллизии ID на допустимом входе.** Цель с ID `v1_ch_1` конфликтовала с новой камерой, давала 23 ошибки валидатора и неоднозначные ссылки. Теперь первый потоковый проход резервирует все входные строки, которые могут совпасть с именами генерируемых объектов, включая ограничения вне окон поиска. Аллокаторы камер, техузлов, линий и summary обходят их; разрезание, слияние и откат используют те же правила. Числовые и остальные строковые ID не преобразуются.
2. **Петля при поиске трассы.** В синтетическом случае A* повторно посещал вершину, чтобы соблюсти направления у концов; результат пересекал сам себя, а проверка дерева его принимала. Новое ребро теперь проверяется на пересечение с предыдущими несоседними рёбрами маршрута. Сглаживание и итоговая постобработка сохраняют простоту; проверка дерева также отклоняет самопересекающийся участок. Отступ для коротких хорд не ужесточён.
3. **CI-зависимость.** `source-map-js` обновлена с 1.2.1 до 1.2.2 — только три поля lock-файла; audit не отключён и его порог не снижен.
4. **Материалы.** Обе презентации содержат подтверждённые капитаном роли и профиль обучения. Удалено двусмысленное объяснение выбора задачи «из-за конкуренции». Текст про проверки описывает найденные ошибки на контрольных результатах, без обещания доказать все правила для любого входа. Предел +10 м в речи заменён точным описанием предпочтения и фактических вводов; резерв +60 м раскрыт. Неподтверждённая дата получения разъяснений удалена из документации и манифеста.
5. **Регламент.** Записано новое разрешение адаптировать отдельный питч после дедлайна. Код и материалы платформы фиксируются до 20.10.2026 23:59 МСК по прежним ссылкам. Точный слот выступления неизвестен.

## Проверки окончательного кода на Windows, Java 11

- Java: 46 тестов; новые регрессии ID и петли сначала падали, после исправлений проходят.
- Python: 30 тестов; 15 синтетических сценариев.
- Основной, строгий и OSM: аудитор, валидатор и контракт — 9 успешных запусков.
- После исправлений заново получены все три GeoJSON, побайтно совпадающие с v3. Основной — из dataset-теста; строгий и OSM — через InputLoader/SolveService/ResultWriter.
- Интерфейс: чистая установка, audit (0 уязвимостей), 7 тестов, typecheck и build.
- Настоящий HTTP upload/start/status/download основного файла — тот же результат побайтно.
- 50 одновременных HTTP-клиентов: 50 завершённых заданий на небольшом двухцелевом сценарии. Это проверка очереди/API, не 50 параллельных расчётов конкурсного квартала.
- Вход 3 221 290 600 байт: настоящий потоковый HTTP upload и расчёт, статус DONE. Синтетика: две цели и 49 386 полигонов вне окон, с текстовым заполнением; не модель города размером 3 ГБ. Upload 12,77 с, upload+расчёт 25,84 с, выборочный пик RSS Java ~308 МиБ, heap ограничен 1024 МиБ. Это числа текущего стенда, не сравнение с экспертами.
- Выгрузка 525 002 414 байт: настоящий ResultWriter и потоковый HTTP download, размер и SHA-256 совпадают. Компонентная синтетика: небольшая рассчитанная сеть с 525 МБ диагностического текста, установленная в отдельное завершённое тестовое задание. Не выдаётся за расчёт сети из сотен тысяч участков.
- Две пары PDF/PPTX: по 12 слайдов, проверена структура и сохранность формата; PDF и превью экспортированы установленным PowerPoint. Все части исходного PPTX, кроме текста четырёх изменённых страниц, сохранены побайтно. Шаблонные геометрия, мастера, логотипы и изображения не перестраивались.

Основной v1: **17/17, S=13,196850094452543, L=1845,704997 м, строительство 273 561 967,97 ₽, штраф 0**. Предупреждения аудитора остаются раскрыты: основной файл — 3 (в v2), строгий — 0, OSM — 6. Валидатор отдельно предупреждает об обоснованных альтернативных вводах. Эти предупреждения не названы ошибками и не скрыты.

## Среда и границы подтверждения

Точные версии приложения заданы в pom.xml и Dockerfile. Workflow на Ubuntu22 проверяет Java, интерфейс, Python, сценарии, основной/строгий результат, современный Compose с PostgreSQL, API и перезапуск. Добавлены отдельные шаги для **официального docker-compose 1.29.2**, с проверкой SHA-256 бинарника, HTTP и сохранностью задания после down/up без удаления томов.

Фактический статус нового удалённого CI записывается в карточке PR/Actions и итоговом отчёте передачи. Описание workflow не является утверждением, что он уже выполнен. Локальные стресс-прогоны использовали профиль без БД, поэтому они не заменяют PostgreSQL/Ubuntu/Compose.

Дата документа 29.09 и хеш оригинала установлены; независимое происхождение от организатора не установлено. Это остаётся раскрытым ограничением источника, а не заменяется выдуманной ссылкой или датой получения. Строгое прочтение сохранено для сравнения.

Факт загрузки на конкурсную платформу, отправки модератору и регистрации на фестиваль не выводится из наличия файлов. Подготовленные материалы и переданные ссылки нужно различать; запись фактической передачи находится в итоговом комплекте.
